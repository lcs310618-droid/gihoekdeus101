# 기획듀스 101 — 내부 멤버용 수정본

2026-10-19. 기존 Firebase 프로젝트와 데이터베이스를 그대로 사용하는 업데이트입니다.

## 적용 순서

1. 기존 `index.html`, `firestore.rules`를 별도로 보관합니다.
2. GitHub에서 기존 `index.html` 전체를 이번 `index.html`로 교체하고 커밋합니다. 기존 배포본의 `firebase-config.js`는 변경하지 않습니다. 첨부 원본의 config에는 예시 값만 있으므로 실제 운영 config를 이 예시로 덮어쓰면 안 됩니다.
3. Firebase 콘솔 → Firestore Database → 규칙에서 이번 `firestore.rules` 전체를 붙여넣고 게시합니다. 코드와 규칙은 한 번의 업데이트로 같이 적용하세요. 두 파일의 버전이 다른 동안에는 등록·투표가 실패할 수 있으니 멤버가 투표하지 않는 시간에 적용합니다.
4. 두 변경이 반영되면 사용자 모두 사이트를 강력 새로고침(Ctrl+Shift+R)합니다.
5. 계란님/우재는 관리 탭에서 기존 명단과 카드를 확인합니다. 결과 공개 시에는 아래의 새 집계 절차를 사용합니다.

`settings/main`을 삭제하거나 새 Firebase 프로젝트를 만들지 마세요. 기존 8개 카드의 ID·내용·회차·작성자 연결을 읽는 방식을 유지하며, 데이터 이전·초기화·일괄 수정 코드는 없습니다. 기존 작성자 연결이 이미 누락되거나 위조된 경우를 자동 복구하지는 않습니다.

## 운영 방식의 변경

- 일반 멤버는 본인 투표 원본만 읽습니다. 다른 사람의 `seen`, 점수 원본은 받지 않습니다.
- 계란님과 우재(ops)는 전체 투표 원본을 읽고 집계할 수 있습니다. 관리 탭에서 실시간 집계를 확인할 수 있습니다.
- 마감 후 계란님 또는 우재가 **관리 → 마감된 결과 전체 집계·공개**를 누르면 일반 멤버에게 합산 결과만 공개됩니다. 종료된 썸네일 배틀도 함께 처리합니다. 자동 18시 공개가 수동 공개로 바뀝니다. 일반 멤버 화면에 0점이 나오면 집계 공개 여부를 먼저 확인하세요.
- 새 투표는 대진과 선택 기록으로 점수를 다시 계산합니다. 저장된 `points`에 큰 숫자를 넣어도 그대로 합산하지 않습니다. 부전승·둘 다 통과·라운드별 누적 가산을 유지합니다. 0~5 누적 제한은 없습니다.
- 이미 저장된 이전 버전 완료 기록은 삭제하지 않습니다. 대진 기록이 없는 기존 완료 결과는 정수·ID·보수적인 누적 범위 검사 후 기존 방식으로 집계합니다. 새 결과는 대진 기록이 필수입니다.
- 업데이트 전 시작했으나 아직 끝내지 않은 월드컵은 해당 투표만 새로 시작하도록 안내합니다. 기존 카드를 다시 등록하는 작업은 필요 없습니다.
- 투표 진행 저장과 집계 등록을 구분합니다. 완료 후 등록이 실패하면 재시도 버튼이 나옵니다.
- 카드/시안/코멘트 생성과 작성자 연결을 묶어 저장합니다. 작성자 연결은 기존 항목을 덮어쓰거나 남의 기존 문서를 새로 추가할 수 없습니다.
- 카드 삭제 시 작성자 연결을 기록으로 남깁니다. 개인 제출 수는 실제 남아 있는 카드/시안을 기준으로 셉니다. 첫 투표가 시작되면 해당 회차 카드 삭제가 잠깁니다.
- 시안 등록/삭제 때 일반 멤버가 배틀 문서를 수정하지 않습니다. 목록의 부정확한 `entryCount` 대신 배틀 안에서 실제 시안 수를 확인합니다.
- 댓글은 카드별로 필요한 범위만 조회합니다. 완료 전에는 본인이 쓴 코멘트, 본인 카드의 코멘트를 읽을 수 있습니다. 남의 코멘트는 본인 완료 기록이 등록됐거나 운영자가 결과를 공개한 뒤 읽습니다. 운영자는 읽을 수 있습니다.
- 공감은 사용자별 기록과 숫자를 트랜잭션으로 함께 바꿉니다. 반복 요청으로 계속 +1 할 수 없습니다. 이전 버전의 공감 수치는 보존하지만 사용자별 서버 기록이 없어 기존 클릭 여부를 완전히 복원하지는 않습니다. 업데이트 후 첫 클릭을 새 방식의 참여로 계산합니다.
- 선정·선정 취소·작성자 공개 필드는 계란님만 바꿉니다. 배틀 상태는 개설자 또는 운영자가 바꿉니다.
- 한국 시간으로 회차/화면 단계를 계산합니다.

## 내부용 구성의 범위

운영자 계정은 신뢰된 계정으로 봅니다. 우재는 작성자 명단 자체를 읽지는 못하지만, 전체 투표 원본을 읽기 때문에 제외된 카드로 작성자를 추정할 여지가 있습니다.

별도 서버를 추가하지 않은 구성입니다. 다음까지 완전하게 막는 버전은 아닙니다.

- 개발자 도구로 대진·선택·완료 기록 전체를 직접 꾸미는 행위. 잘못된 대진은 집계에서 제외하지만, 정상 형식의 전체 대진 기록을 위조하는 것은 서버가 실제 화면 조작과 구별하지 못합니다. 댓글의 완료 조건도 서버가 검증한 참가 증명은 아닙니다.
- 클라이언트의 마감 시각·제출 상한 우회. 화면 검사는 유지하지만 서버 시각 기반의 접수 마감/쿼터는 추가하지 않았습니다. 배틀 투표는 서버 규칙에서도 `vote` 상태인지 확인합니다.
- 모집 중 남의 시안 사전 열람과 라운드별 상세 사전 열람. 내부 멤버에게 자료 자체는 읽기 허용하고 화면에서 공개 단계를 나눕니다.

이 범위까지 막으려면 신뢰된 서버의 투표 진행·검증이 필요합니다.

## 확인한 항목과 한계

- 인라인 JS 문법 검사 통과.
- 2~30장, 둘 다 통과 0~3 설정의 1,392개 시나리오에서 종료·점수 재계산 일치·큰 점수 변조 무시 확인.
- 가상의 기존 카드 8장으로 화면 렌더링, 본인 카드 제외, 일반 멤버/운영자 구독 분리, 익명 공개 집계, 집계 등록 재시도·중복 처리, 이미지 속성 이스케이프 확인.
- 실제 운영 Firebase 연결 정보가 첨부되지 않아 운영 DB의 카드 내용 확인, Firebase Emulator 실행, 실제 보안 규칙 게시·동작 검증은 수행하지 못했습니다. 실제 운영 사이트는 수정하지 않았습니다.
